# Product Backlog

This backlog intentionally contains a small set of items that are still immature.
The purpose is to use product context, evidence, and team agreements to refine them.

---

## Parking Reservation

Allow employees to reserve parking spaces before arriving at the office.

### Current Status

Needs refinement.

### Known Questions

- Is reservation actually necessary to solve the user problem?
- How long should a reservation remain valid?
- What should happen if a user does not show up?
- Should users reserve a specific space or simply capacity?
- What evidence supports this solution?

---

## Real-Time Availability

Show employees how many parking spaces are currently available.

### Current Status

Needs refinement.

### Known Questions

- What level of accuracy is acceptable?
- How frequently must the data be updated?
- Which data source will provide availability information?
- Should availability be shown as an exact number or an estimate?

---

## Parking Map

Allow users to view parking areas on a map and select a specific parking space.

### Current Status

Needs validation.

### Known Questions

- Is choosing a specific space a real user need?
- Is there enough evidence to justify this capability?
- Are there accessibility scenarios that require space selection?
- What additional complexity would this introduce?

---

## No-Show Handling

Automatically release reservations that are not used.

### Current Status

Depends on whether reservations become part of the product.

### Known Questions

- How do we detect a no-show?
- How long should the grace period be?
- What happens when sensor data is delayed or inaccurate?
- Should repeated no-shows have consequences?

---

## Notes

Backlog items should not be considered ready only because they have been written down.

They should be evaluated against:

- Product Vision
- Business Goals
- User Research
- Definition of Ready
- Known risks and dependencies
